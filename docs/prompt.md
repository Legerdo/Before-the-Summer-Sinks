# 고품질 2D 비주얼 노벨 자율 제작

Windows 11 환경에서 사용 가능한 개발 도구와 에이전트 기능을 활용하여, 처음부터 끝까지 완결된 고품질 비주얼 노벨 게임을 실제로 제작하라.

단순한 기술 데모나 짧은 프로토타입이 아니라, 스토리·캐릭터·비주얼·음향·연출·UI·게임 시스템이 하나의 작품으로 느껴지는 완성품을 목표로 한다.

## 핵심 목표

첫 플레이 기준 약 **1~2시간** 정도의 적당한 분량으로 만든다.

분량을 억지로 늘리기 위한 반복 대사, 의미 없는 선택지, 과도한 서브플롯은 넣지 않는다. 반대로 짧은 데모처럼 끝내지도 않는다.

하나의 강한 중심 소재와 기억에 남는 메인 히로인을 중심으로 기승전결이 완결되는 이야기를 직접 설계하라.

스토리는 라이트 노벨/비주얼 노벨 장르에서 기대하는 수준의 흡입력 있는 문체, 캐릭터성, 감정선, 복선과 회수, 장면 전환, 긴장과 완급 조절을 갖추어야 한다.

설정만 거창하고 실제 사건이 없는 이야기가 아니라 플레이어가 계속 다음 장면을 보고 싶게 만드는 서사를 우선한다.

한국어를 기본 언어로 한다.

## 작품 방향

캐릭터와 주요 비주얼은 **고품질 2D 일본 애니메이션·만화 스타일**의 오리지널 디자인으로 제작한다.

특정 기존 작품이나 작가를 복제하기보다 작품 자체의 일관된 아트 디렉션을 먼저 정하고, 이후 모든 캐릭터·표정·CG·배경·UI가 그 방향을 유지하도록 한다.

메인 히로인은 외형뿐 아니라 말투, 가치관, 행동 방식, 약점, 관계 변화가 분명한 인물로 만들어라.

캐릭터 수와 분기 수는 많을 필요 없다. 1~2시간이라는 범위 안에서 **넓이보다 밀도와 완성도**를 우선한다.

선택지가 있다면 실제 대화, 관계, 장면 또는 결말에 의미 있는 영향을 주도록 하고 선택지 개수를 늘리기 위한 선택지는 만들지 않는다.

## 비주얼 제작

필요한 캐릭터 스프라이트, 표정 차분, 배경, 이벤트 CG, UI용 이미지 등은 사용 가능한 **Codex 이미지 생성 기능을 적극 활용하여 직접 제작**할 수 있다.

작업을 시작하기 전에 현재 Codex 환경에서 실제 사용할 수 있는 이미지 생성 tool/skill/CLI를 확인하고 가장 적절한 방법을 선택하라.

빠른 초안 → 실제 화면 확인 → 문제 수정 → 최종 에셋 생성의 순서로 작업하고, 처음 생성된 결과를 무조건 최종본으로 사용하지 않는다.

같은 캐릭터가 장면마다 다른 사람처럼 변하지 않도록 디자인 기준과 레퍼런스를 유지하고, 이미지 생성 결과를 게임 안에서 직접 확인하면서 필요하면 재생성하거나 수정하라.

캐릭터 이미지를 단순히 화면에 세워두는 수준에서 끝내지 말고 현대적인 비주얼 노벨에 어울리는 생동감을 구현한다.

예를 들어 상황에 적합한 범위에서 다음을 활용할 수 있다.

- 자연스러운 눈 깜빡임과 시선 변화
- 입 모양 애니메이션
- 표정과 자세 변화
- 미세한 호흡이나 idle motion
- 캐릭터 등장/퇴장과 화면 이동
- 카메라 이동, 확대, 흔들림
- 레이어와 parallax
- 분위기에 맞는 장면 전환과 화면 효과

모든 효과를 넣는 것이 목적은 아니다. 장면의 감정과 연출에 실제 도움이 되는 것만 사용하라.

## 히로인 음성 — Fish TTS

메인 히로인의 주요 대사는 **Fish TTS를 이용한 음성 연기**를 제공한다.

현재 환경에서 사용할 수 있는 Fish TTS/Fish Audio 버전과 실행 방식을 먼저 확인하고, 기존 설치가 있다면 그것을 우선 활용한다. 필요한 설치가 있다면 프로젝트와 격리된 안전한 환경을 사용한다.

히로인의 목소리는 작품에 맞는 일관된 오리지널 음색으로 유지한다. 실제 인물이나 성우의 목소리를 무단으로 모방하지 않는다.

가능한 범위에서 단순한 평면 TTS가 아니라 장면별 감정을 반영한다.

예:
평상시 대화, 웃음, 당황, 분노, 슬픔, 속삭임, 긴장, 감정이 북받치는 장면 등.

단, 감정 태그를 기계적으로 남발하지 말고 실제 연기처럼 자연스럽게 유지한다.

히로인의 대사는 가급적 풀보이스화하되, 주인공 독백이나 서술까지 무리하게 음성화하여 제작량을 부풀릴 필요는 없다.

각 음성 파일과 대사에는 안정적인 ID를 사용하여 스크립트와 연결하고, 이후 대사가 수정되어도 음성 관리가 꼬이지 않는 구조로 만든다.

### 립싱크

히로인이 말할 때 실제 음성과 맞춰 입 모양이 움직이게 한다.

단순히 일정한 속도로 입을 열고 닫는 가짜 애니메이션보다는 실제 재생 중인 음성의 발화와 휴지를 반영하도록 구현한다.

가능하면 음성 분석 결과를 이용하여 자연스럽게 입 모양을 제어하고, 말하지 않을 때는 확실하게 닫히도록 한다.

눈 깜빡임, 표정 변화, 음성, 입 모양이 서로 따로 노는 느낌이 없도록 실제 게임 화면에서 검증하라.

## 사운드와 연출

BGM, 효과음, UI 사운드, 환경음도 작품의 분위기를 구성하는 중요한 요소로 취급한다.

필요한 경우 사용 가능한 생성 도구나 직접 제작 가능한 방법을 활용해 작품에 맞는 사운드를 준비할 수 있다.

외부 에셋을 사용할 경우 라이선스를 확인하고 출처가 불명확한 저작물을 임의로 포함하지 않는다.

특히 중요한 장면에서는 그림 한 장과 텍스트만 바꾸는 식으로 끝내지 말고, 음악·음성·표정·타이밍·카메라·효과를 조합해 장면 자체를 연출하라.

## 비주얼 노벨 시스템

현대적인 상용 비주얼 노벨에서 자연스럽게 기대되는 기능은 빠뜨리지 않는다.

예를 들어 다음과 같은 플레이 경험을 고려하라.

- 저장/불러오기 및 빠른 저장
- 대사 로그
- Auto
- Skip 및 읽은 대사 처리
- 음성 다시 듣기
- 개별 음량 조절
- 전체화면/창모드와 해상도 대응
- 자연스럽고 빠른 텍스트 출력
- 선택지와 분기
- 설정 유지
- 게임 재실행 후 정상적인 진행 복구

UI는 기능을 나열한 개발자 도구처럼 보이지 않게 하고 작품의 아트 디렉션과 통합한다.

스토리 데이터, 대사, 분기, 음성, 이미지 에셋의 연결은 가능한 한 data-driven하게 구성하여 콘텐츠가 코드 전체에 하드코딩되지 않게 한다.

## 기술 선택

특정 프레임워크나 엔진을 억지로 사용할 필요는 없다.

현재 환경, 개발 속도, 비주얼 연출, 오디오 처리, 배포 및 유지보수성을 고려하여 이 작품에 가장 적합한 기술 스택을 스스로 선택하라.

다만 기술적으로 화려한 구조를 만드는 것이 목표가 아니다. 최종 플레이 경험이 더 좋아지는 선택을 우선한다.

새 라이브러리나 도구를 도입한다면 단순히 유명해서 넣지 말고 실제 필요한 경우에만 사용한다.

## 작업 방식

먼저 작품의 핵심 콘셉트와 기술 구조를 내부적으로 정리한 뒤 바로 제작에 들어가라.

사용자가 결정하지 않아도 되는 창작상의 세부사항은 스스로 결정한다.

여러 아이디어를 나열하고 사용자가 하나를 선택하기를 기다리지 마라. 가장 강한 방향을 하나 선택하여 끝까지 발전시킨다.

진행 중 문제가 생기면 단순 우회로로 덮지 말고 원인을 확인하고 수정한다.

긴 작업에서는 중요한 단계가 끝날 때만 짧게 진행 상황을 알려라. 매 파일 수정마다 보고할 필요는 없다.

사용자의 확인이 정말 필요한 외부 계정, 결제, 배포, 되돌리기 어려운 작업 등이 아니라면 불필요하게 중단하지 말고 계속 진행한다.

Git commit, 원격 push, 공개 배포는 별도 요청이 없다면 수행하지 않는다.

## 품질 기준

완료의 기준은 코드가 실행된다는 것이 아니다.

실제로 플레이했을 때 다음 조건을 만족해야 한다.

- 처음부터 끝까지 진행 가능한 완결된 이야기
- 약 1~2시간의 자연스러운 플레이 분량
- 메인 히로인의 캐릭터성과 관계 변화가 분명함
- 스토리가 중간에 급하게 끊기거나 설정 설명만 하다 끝나지 않음
- 아트 스타일과 캐릭터 외형이 장면 사이에서 일관됨
- 히로인 음성이 실제 게임에 정상적으로 연결됨
- 음성과 입 모양이 자연스럽게 동기화됨
- 표정, 음성, 음악과 연출이 장면의 감정과 맞음
- save/load, skip, auto, backlog 등 핵심 VN 기능이 정상 동작함
- 누락된 이미지, 음성, 깨진 경로, 임시 placeholder가 없음
- 기본 UI가 프로토타입처럼 보이지 않음
- 일반적인 해상도에서 레이아웃이 깨지지 않음
- 치명적인 콘솔 오류나 진행 불가 버그가 없음

## 반드시 실제 검증할 것

구현이 끝나면 빌드 성공만 확인하고 완료했다고 하지 마라.

게임을 직접 실행하고 대표 장면들을 화면으로 확인한다.

초반, 일상 대화, 감정적으로 중요한 장면, 선택지, 이벤트 CG, 클라이맥스, 엔딩 등을 실제 렌더링 상태에서 검토한다.

전체 루트는 디버그용 빠른 진행이나 자동화를 활용해서라도 처음부터 엔딩까지 통과시켜 다음을 확인한다.

- 잘못 연결된 분기
- 누락된 대사
- 없는 이미지나 음성
- 대사와 음성 불일치
- 음성 중복 또는 잘림
- 립싱크 오류
- Save/Load 후 상태 손실
- Skip/Auto 문제
- 장면 전환 오류
- 캐릭터 일관성 문제
- 지나치게 길거나 늘어지는 구간
- 갑작스럽거나 설명이 부족한 전개

발견된 문제는 수정하고 다시 검증하라.

플레이타임은 단순한 타이머 대기나 불필요한 텍스트로 1~2시간을 맞추지 말고 실제 대사량, 음성 길이, 장면 구성 및 일반적인 독서 속도를 기준으로 판단한다.

## 최종 목표

기능 목록을 전부 체크한 프로젝트보다,

**“짧지만 상업 비주얼 노벨 한 작품을 제대로 플레이했다”는 느낌이 드는 게임**

을 만드는 것이 최우선이다.

필요한 이미지와 음성까지 실제로 제작하고 게임에 연결하며, 구현 → 실행 → 플레이 → 시각·청각 검토 → 수정의 루프를 반복하라.

작품의 창작적 방향과 세부 구현은 네 판단을 적극적으로 사용하되, 위 품질 기준을 낮추는 방향으로 범위를 축소하지 마라.

끝까지 완성하고 실제 검증된 상태에서만 완료를 선언하라.
